# Walk-forward discovery

`combiner.predict()` runs discovery when `config.DISCOVERY` is true. Each year
uses target months from February 2015 through the previous December. Formation
rows therefore stop in November of the previous year. No test-year labels are
loaded to evaluate or score that year's proposals.

The researcher uses two three-proposal rounds per pod. Admission preserves the
prototype's fixed S, shuffled-control, spread-t, correlation and capacity gates.
The recent-strength component rolls with the target year. These are adaptive
selection statistics, not unbiased estimates of future performance.

Sources are the official characteristics, official 8-K item counts, trailing
DSF features, and the explicitly authorized owned Carbon extracts. The owned
loader reads the canonical unified card and foot-traffic files, ignores stored
PERMNOs and precomputed growth features, maps observation-month ticker labels,
and delays availability by one month (unknown tear-sheet lag). It cannot
reconstruct historical revisions to the extracts. Panel descriptions come from
the existing JKP workbook; `intrinsic_value` retains its supplied feature name.

Research responses and free Carbon metadata/quotes live in
`final_v3/discovery_cache/`, outside the work directory cleared by main.
`FIAM_DISCOVERY_OFFLINE=1` permits cached responses only; any missing research,
scout, search or quote response raises. Source parquet caches can still be built
from local files offline. Credentials are read only when a live call is needed.

The Carbon adapter uses MCP/OAuth for catalogue search. Legacy REST dollar quotes
are explicitly unavailable and cannot trigger a purchase. Existing owned dated
extracts remain available to research. The versioned MCP cache preserves old REST
receipts without reusing them as new evidence. Team-account analytical acquisition
requires an explicit supported MCP request; scouting is not a data download.
